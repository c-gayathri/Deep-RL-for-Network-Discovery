# Training and experiment notes

## Training flow

Each episode performs the following high-level sequence:

1. Select a graph and initial seed nodes.
2. Build the currently discovered subgraph and compute DeepWalk node embeddings.
3. Choose query actions with the DQN policy or epsilon-greedy exploration.
4. Expand the discovered network and update the environment reward.
5. Add the transition to prioritized replay and update the value networks.
6. Evaluate influence on the full graph at the end of the sampling budget.
7. Record metrics and periodically save a model checkpoint.

`train.py` records the final influence measurement. `train_fairness.py` additionally records discovery, spread, and community-level metrics.

## Important command-line arguments

| Argument | Purpose |
| --- | --- |
| `--eps` | Number of training episodes. |
| `--sample-budget` | Number of node queries allowed in an episode. |
| `--extra-seeds` | Number of initially observed seed nodes. |
| `--samples` | Number of Monte Carlo samples for influence estimation. |
| `--infl-budget` | Number of nodes selected by influence maximization. |
| `--buffer-size` | Replay-buffer capacity. |
| `--batch_size` | Gradient-update batch size. |
| `--gcn_layers` | Graph-convolution layers before pooling. |
| `--lr` | Learning rate. |
| `--gamma` | Discount factor. |
| `--epsilon` | Exploration probability. |
| `--eps_decay` | Per-episode epsilon decay. |
| `--walk_len` | DeepWalk walk length. |
| `--num_walks` | Number of walks per graph. |
| `--win` | Word2Vec context-window size. |
| `--emb_iters` | Word2Vec training epochs. |
| `--use_cuda` | Use CUDA when set to `1`. |
| `--write` | Write TensorBoard metrics when set to `1`. |
| `--fileName` | Raw result output path. |

Run `python train.py --help` or `python train_fairness.py --help` for the complete set of options.

## Data and generated files

Input networks are stored under `data/`. The `data/graphs/` directory contains synthetic graphs and parameter bundles retained from the experiments.

The following are generated locally and excluded from version control:

- model checkpoints under `models/`;
- TensorBoard data under `runs/`;
- log files under `logs/`;
- raw experiment outputs under `results/raw/`;
- plots generated by `scripts/plot_results.py` under `results/generated/`.

Selected result figures that form part of the project record are kept under `results/figures/`.
